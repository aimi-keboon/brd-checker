BRD Direction Builder

Upload stakeholder notes, meeting summaries, or rough ideas.
This tool helps you understand what must be clarified before writing a proper BRD.

What to Include for Best Results

Try to include as many of the following as you reasonably can:

  • Business problem or objective (why this is being done)
  • Who requested this (stakeholders, departments)
  • Target users (who will use it)
  • What is in scope (high-level features or changes)
  • What is explicitly out of scope (if known)
  • Any deadlines or constraints (regulatory, timeline, budget)
  • Integrations or systems involved (if mentioned)
  • Known risks, concerns, or open questions
  • Anything stakeholders disagreed on

It’s okay if you don’t have all of this. Missing information is exactly what the tool will help identify.

Example Input (You Can Copy This Structure)

Business Objective: - Improve payment reconciliation accuracy for retail stores Stakeholders: - Finance team - Store operations - IT Current Situation: - Reconciliation is done manually using Excel - Errors are common and discovered late Proposed Idea: - Integrate POS system with payment gateway reports - Generate daily reconciliation summaries Known Constraints: - Must work with existing POS system - No changes to payment gateway contracts Open Questions / Concerns: - How discrepancies should be handled - Who owns exception resolution
